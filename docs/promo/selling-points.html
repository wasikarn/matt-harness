A Claude Code harness that won't let the model grade its own work.

Ten selling points, each grounded in a file you can open. The unifying claim: gates that block bad actions are deterministic shell. Sensors that nudge are journal-only. The model is the maker, never the checker.

17 agents 59 skills 9 deny-gates 7 advisory sensors SessionStart doctrine injection pre-push gauntlet · 6 layers verifier separation

  1. The maker is not the checker

    The whole harness rests on one rule: a model grading its own output is a verdict the model shouldn't get to make. Gates that block bad actions are deterministic shell scripts that return a branchable score. Sensors that nudge are journal-only and never emit a deny decision. The only way to ship is through a gauntlet that branches on a number, not on what the model rationalizes.

    Why this matters: an LLM cannot verify itself. The verifier separation principle is built into the runtime itself — advice and denial are different layers, kept separate on purpose. CLAUDE.md · Architecture · Why — the unifying crux

  2. Doctrine is injected at session start

    Every Claude Code session begins with docs/METHODOLOGY.md pushed into context by a SessionStart hook. No @import, no manual load. The decision-sizing triad (one-way door · blast radius · riskiest assumption) is in scope before the first tool call.

    Two more doctrine files stay close at hand but are read on demand: CLAUDE.md's Architecture section for the operating model, and BOUNDARY.md for the live surface inventory. hooks/session/doctrine-bootstrap.sh docs/onboarding.md

  3. 9 deny-gates block the irrecoverable set

    Nine PreToolUse hooks run as deterministic shell. The irrecoverable set — rm -rf, --no-verify, worktree creation on protected paths, edits to the gates themselves, db writes, credential edits, config rewrites, Atlassian MCP writes, task-complete self-verification — is denied before the model can grade it. No env-var bypass.

    The single most load-bearing of these is hooks/gates/verifier-protect.sh. It asks for explicit human approval before any edit to hooks/gates/**, hooks/hooks.json, or the harness-audit verifier. The invariant: the gate that authorizes a mutation or ship stays computational, never a model. hooks/gates/irrecoverable.sh hooks/gates/worktree-guard.py hooks/gates/db-write-gate.sh hooks/gates/credential-guard.sh

  4. 7 advisory sensors journal, never deny

    Seven PostToolUse / SessionEnd hooks surface nudges — flow state, loop repetition, plan-review timing, compliance-audit timing, learn moments, jira routing, MCP failure patterns. They write to a journal and exit. They never emit permissionDecision: deny.

    The boundary is intentional: a sensor that could also deny is a sensor the model could prompt-inject itself past. Keeping them advisory-only is the same verifier-separation rule, applied to the observation layer. hooks/advisory/ CLAUDE.md · Architecture · Operating model

  5. The ship gauntlet runs 6 layers in parallel

    Every push runs the full gauntlet before anything leaves the machine: plugin-validate, full shell-lint, JSON lint, harness-audit, the behavioral test suite, plus the file-list checks. Pre-commit is the fast gate (4 parallel layers including the new-file LOC cap). Harness-audit's CRIT findings block ship outright.

    The gauntlet is deterministic: every layer returns a branchable score. If any layer fails, the push does not land. There is no "the tests passed, ship anyway." scripts/run-gauntlet.sh git-hooks/pre-push git-hooks/pre-commit

  6. Version-bump gate stops cache drift

    Same-version edits to a cached plugin are silent no-ops — Claude Code keys updates on the manifest version. The pre-commit hook blocks any commit that touches a shipped surface (agents/, skills/, hooks/, output-styles/, themes/, scripts/, contexts/, docs/METHODOLOGY.md, docs/reference/**) without bumping plugin.json + marketplace.json in the same commit.

    Both manifests must agree, and deletions count too. The gate was extended after three scripts-only commits silently never reached the installed cache. CLAUDE.md-only edits skip the bump because no shipped surface reads CLAUDE.md from the cache. git-hooks/pre-commit

  7. Tiered pipeline: Fable plans, Sonnet executes, Opus reviews

    For non-trivial work, the skills/workflow/tiered-pipeline skill routes by phase. A frontier model produces the plan. Sonnet-class execution writes the code. Opus-class review re-reads the diff against the plan and applies code-counted fix caps. Then a bug-hunt pass and a gated final review.

    The pipeline is structured but prompt-only — no gate enforces model selection. Same honesty as Rule 14 below.

  8. Rule 14 score-decision rubric

    For decisions that have to land in one shot, the skills/meta/score-decision skill scores a shortlist against an explicit rubric, with named weight reasoning. The output is a single number plus the rubric breakdown — a deterministic-shape answer that survives the model's tendency to hedge.

    The rubric is prompt-only: no hook enforces that the operator used the skill, and no gate grades the score. Use it because it forces the criteria into the open, not because the framework guarantees a particular result.

  9. A self-auditing fleet

    harness-audit runs the in-repo skills/meta/harness-audit/scripts/audit.sh over the fleet — agents, skills, hooks, output-styles, themes, commands. CRIT findings block ship; WARN findings are tracked. Decay-sweep cadence runs quarterly to prune dead weight before it accumulates. BOUNDARY.md is the always-current inventory of every surface, regenerated by inventory-witness.sh.

    17 agents, 59 skills, 1 output style. Each ships with a bucket: frontmatter that groups the BOUNDARY.md tables by purpose (meta · review · patterns · agent-support · design · workflow). Skill descriptions stay under 25 words because they load on every Task spawn.

  10. Backend-stack support built in

    Beyond the harness core, the plugin ships opinions and patterns for Drizzle ORM, MySQL/MariaDB, and gRPC service design. These are skills and agents the operator can pull into any session — not a framework lock-in, but tested defaults that have already survived the gauntlet.

    .claude-plugin/marketplace.json keywords capture the surface at a glance: harness · agents · skills · workflow · governance · doctrine · hooks · ship · research.

The hardest part of an agent loop is not making the model smarter. It is keeping the model out of the loop that grades the model. This harness is one answer — opinionated, sharp-edged, and built around the rule that gates stay shell and the maker never gets the last word.
