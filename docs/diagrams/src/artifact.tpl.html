01

What the plugin does

Claude Code has its own request lifecycle. This map is not it. What you are looking at is the plugin's own work, and it lands in three moments. Before the model does anything, the plugin injects its doctrine and loads the skills and agents. While the model works, it denies the actions nobody can undo and quietly journals everything else. Afterwards it grades the result.

Look at the two nodes drawn with the dark fill. They are the only things in the picture that are not a model. A model grading its own output is two optimists agreeing, so the gate is shell and so is the verifier.

Where the work quietly doesn't ship

Edit a cached plugin without changing its version and nothing happens. No error, no warning. Bump both manifests, run claude plugin update, restart.

02

Session lifecycle and hook dispatch

The plugin wires nine Claude Code events. Eight of them route through hooks/dispatch-single.sh first. That script is a filter, and it can drop a hook before the real script ever runs. PreToolUse is the exception, and it has a dispatcher of its own.

Tiers are ordinal. minimal is 0, standard is 1, strict is 2, and a hook fires when its own tier sits at or below the active profile. MH_HOOK_PROFILE defaults to strict, which means an untouched environment runs everything. You have to opt into the quiet.

TierBehaviourTypical carrier
minimalAlways on. Switching it off costs you a feature.doctrine injection, env-var anchor, cost tracking
standardOn by default. The first thing to drop when you want a quieter session.advisory nudges, memory health
strictOnly in the loudest profile.end-of-session learn prompt, stale-task nudge
The id prefix lies

Three hooks carry a session: prefix and none of them run on SessionStart. skill-usage-telemetry runs on PostToolUse, precompact-state-flush on PreCompact, instructions-loaded-journal on InstructionsLoaded. Check hooks.json when you need the real mapping.

Everything under hooks/gates/ can deny. Everything under hooks/advisory/ journals and nudges, and never emits permissionDecision. A model can argue with context. It cannot argue with a gate.

03

Advisory sensors

This is the advise half of the operating model. Section 04 covers the deny half. Seven sensors watch four events, and none of them emits permissionDecision. Grep across hooks/advisory/ confirms that, which is the only way to know it: a header comment claiming a script never blocks is not the same thing as the script never blocking.

A sensor produces two things. Text that goes into the turn, which the model can weigh or ignore as it likes. And state on disk, so the next turn knows what the last one saw. Neither is a verdict.

They count, they don't judge

loop-repeat-nudge counts identical {tool, params} pairs. It never decides whether a session is spinning. mcp-failure-nudge reads failures Claude Code has already surfaced and never probes a server itself. A sensor that judged would be a gate wearing the wrong label.

04

PreToolUse gate fan-out

hooks.json carries a single PreToolUse registration. It fans out in parallel to every gate whose matcher matches the tool call in front of it.

A missing python3 fails open. Each gate underneath already fails open on its own, so doing it once at the top gets the same result with one stderr note instead of a pile of duplicates. An unparseable table fails closed instead. The alternative is a traceback that silently switches off every gate at once, and that is the worse outcome.

BehaviourEntries
denygate:bash:irrecoverable, gate:bash:worktree-guard, gate:task:complete-separation
askgate:write:verifier-protect, gate:bash:verifier-protect, gate:db:sql-write, gate:write:config-guard
blockgate:read:credential-guard, on Read and Grep
markergate:skill:jira-acli-engage. Never blocks; it sets session state so its companion can allow-list.
no-opBoth worktree-guard entries need MH_GUARDED_WORKSPACE. gate:db:sql-write never fires without a matching MCP server.

There are more table entries than gate scripts. verifier-protect, atlassian-mcp-gate, and worktree-guard-dispatch each register twice under different matchers. The gate: prefix promises nothing on its own, so read the behaviour column.

verifier-protect is the tamper resistance

It asks a human before any edit to hooks/gates/**, hooks/advisory/**, hooks/hooks.json, or the harness-audit grader. The model cannot quietly edit the code that judges it. There is no env-var bypass either.

05

Ship path

Wire the two git hooks once per clone, with git config core.hooksPath git-hooks, and keep that path relative.

Keep core.hooksPath relative

An absolute path dies the moment somebody renames the directory, and it dies quietly. Git says nothing when core.hooksPath points somewhere that no longer exists. It just runs no hooks at all. test -d "$(git config core.hooksPath)" is a cheap way to check.

gate:bash:irrecoverable denies --no-verify, so the only way past either hook is to fix what it found.

The repo is public, so the path check looks for the account name in three shapes: the slash path /Users/<name>, the dash-encoded form Claude Code uses to key a project directory, and the bare name sitting in prose with no path around it. That third shape exists because a purge once reported the repo clean while occurrences sat in CHANGELOG.md and docs/research/. Those directories are frozen against wording sweeps. Somebody read that as a hygiene exemption too, and it is not one.

06

Adding or removing a surface

Auto-discovered directories: agents/, skills/, hooks/, output-styles/, themes/.

Refresh the cache before you commit

The pre-commit harness-audit only ever sees the latest cached plugin version. A brand-new file will block as CRIT F1 until the cache catches up.

The same staleness bites when you re-verify an edit in the same session. Do not hand a verification agent a name-based reference: Skill(<name>), a subagent_type, a slash command. If the edit has not been bumped and reinstalled, every one of those resolves to stale cached content and nothing errors. Tell the agent to Read the repo path instead.

07

Orchestrate dispatch loop

For a pile of competing asks. The lead decides what goes where; subagents do the work.

The loop exists to stop three things. One of them already happened here: a prompt asking for 20 to 35 items produced 44, and the audit and verify passes doubled that to 105 agents. The other two are what the skill guards against. A planning question is not approval to execute. And a research brief passes every automated check going, because there is no code in it to compile, so corroborating its citations is the only gate it ever meets.

A subagent can't sign off on itself

gate:task:complete-separation denies TaskUpdate(status=completed) whenever an agent type is present. The maker does not get to be the checker.

08

Memory loop

Because the top layer loads on every single session, it carries a hard byte cap. The three below it do not.

One fact per file, typed user, feedback, project, or reference. When the index nears its cap, shorten each entry to a single line and push the detail down a layer. Do not delete the backing file.

Tool-clean governs

When memory-lint reports clean, stop there. Shaving index lines by hand to hit a soft target is scoring by feel, and this harness scores by number.

09

Tiered pipeline

The headline multi-model review loop: Fable plans, Sonnet executes, Opus reviews with a counted fix loop, Fable re-reviews behind a triage gate.

{{D9}}
Structured but prompt-only

Model selection is prompt-only. No script enforces which tier runs at each stage. The fix loop is counted in code at three retries; everything else is discretionary. Same maker-not-checker rule as the gates: a script can count, but it cannot pick.

10

Rule 14: score-decision rubric

A formal decision verdict: stated criteria + weights + numeric result + pass/fail + confidence. A pass threshold AND a fatal-weakness floor must both hold. Precedent is queried first.

{{D10}}
Structured but prompt-only

No script enforces model choice, the weights, or the floor. The rubric gives a defensible structure for a decision the model is about to make anyway; what it cannot do is veto the model. Same honesty as the gates: a script can score, but it cannot reason.
